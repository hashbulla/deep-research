### Added

- **Rule 7c — the agent-skill class, and a gate that enforces it.** Where the capability under study is consumed BY an agent, the packaged-skill class is where the state of the art actually lives — and tool vocabulary cannot reach it, however many topic combinations run, because a skill's topics describe *how an agent consumes it*, not *what it does*. A skill is a **delivery form, not a tool category**. Measured 2026-08-13 (Excalidraw toolchain run): **ten** topic combinations swept — `excalidraw`, `mcp`, `diagram-as-code`, `c4-model`, `tldraw`, all tool vocabulary — and the skill ecosystem was missed entirely; skills surfaced only incidentally, as by-products of the MCP sweeps. The corrected sweep returned **42 repos** under `topic:claude-code+topic:excalidraw` and **8,192 `SKILL.md` files**, including a **4,411-star** skill carrying the *design methodology* the report was missing (concept-mirroring patterns, a semantic palette, a render-and-verify loop). The report had answered "which tool renders the file" and never "what makes the output good", because the class that answers the second question was never queried. New pipeline step `references/github-research.md` §2b — four mandated query shapes, with `anthropics/skills` **always** checked (an official skill outranks every third-party one, and its *absence* is itself a finding) and the curated aggregators named. New gate **Rule 7c** (`verify_gates.py`): an `open-source` category marked `swept`/`empty` on a Claude/agentic question requires ≥1 skill-class query (a `topic:` facet among `SKILL_TOPICS`, or a `filename:SKILL.md` code search). `_is_agentic_question()` reads the manifest's question text and declared platforms **only — never its findings**, since reading findings would let a thin sweep exempt itself by omitting the very queries the rule demands. New fixture pair `agentic-no-skill-query.json` (violation) and `agentic-with-skill-query.json` (positive control), taking the solution-space set to **16**; the pair is byte-identical outside `open-source.queries`, the single field the rule reads. The control carries all four step-2b shapes rather than the one query that would merely clear the gate — run #4's DIM-4-02 caught exactly that gate-conformant-but-not-doctrine-conformant gap on this fixture set. `check-solution-space.sh` gains the 7c assertion, a 7c purity guard, and the positive-control block; the golden `valid.json` now doubles as a standing negative control (non-agentic question, no skill query, must never trip 7c). **Red-ability verified by ablation**: disabling the rule turns `check-solution-space` FAIL on the new fixture. Signalled by Victor after the Excalidraw delivery — "a SOTA method on Claude or agentic integration should ALWAYS look for the SOTA skills".
- **Software-capability tier path — code is primary evidence.** `references/methodology.md` §6 gains a grading path for software-capability questions: behaviour **executed** or source **read** grades **Tier 1**, independent of popularity; a project's README about *itself*, plus corroborated adoption, grades Tier 2; a README about its *rivals* never grades above Tier 3. **Stars alone lift nothing.** Measured on the Excalidraw run: keying promotion to adoption — downloads, dependents, fork ratio — *demoted* two of the report's own recommendations (`excalidraw-cli` at 97 downloads/week; `drawmode` at 16 stars) and *promoted* the official converter at 477,801 downloads/week. A star-keyed rule would have done the exact opposite. `verify_gates.py` adds `direct_observation` to `SCORELESS_TOOLS`: primary evidence generated by the run itself never passed through a retrieval engine, so it carries no Tavily score by construction, and §6 requires the verification be described in `notes`.
- **GitHub-native OSS sweep — the `topic:` facet, and a gate that enforces it.** The solution-space manifest could previously carry `open-source: swept` on prose queries alone; nothing distinguished "swept via GitHub" from "swept via blogs about GitHub". Root cause measured 2026-08-05: a hand-run web-interaction benchmark declared `open-source` swept on Tavily prose and missed **8 repositories totalling ~200k stars**, the top one (`Panniantong/Agent-Reach`, 66,684 ★, Chinese-first README, tagged `claude-code`) being the **first of 11 hits** on `topic:claude-code+topic:web-scraper&sort=stars`. Prose retrieval surfaces comparison blogs — written by vendors comparing vendors — and is structurally blind to a category whose vendors do not blog, or whose README is in another language. **New pipeline step** (`references/github-research.md` §2, now ordered *before* star-band sharding): sweep ≥3 `topic:` combinations derived from the capability classes, sorted by stars, recorded verbatim in `categories[key=open-source].queries`. Topics are an author-assigned, language-independent controlled vocabulary — the one retrieval axis immune to "my query words encode my hypothesis" (B14 taken one level deeper). **New gate Rule 7b** (`verify_gates.py`): a `swept` or `empty` `open-source` category with no GitHub-native query fails; `GITHUB_NATIVE_QUERY` matches a `topic:` facet, a `stars:` band, `api.github.com/search`, or `gh api`/`gh search` — and deliberately **does not** match `site:github.com`, which is prose retrieval wearing a GitHub costume. New violation fixture `oss-prose-only.json` (12 adversarial fixtures, up from 11); the golden `valid.json` **was itself carrying the defect** and now holds a GitHub-native query. New regression case `wi` in `evals/fixtures/sota-recall/` (`wi-brief.md` + 2 ground-truth items: Agent-Reach and OpenCLI — 6 items across 3 cases, up from 4 across 2), where the recall property is that both surface through a topic sweep and neither is reachable from English prose describing the problem.
- **Solution-space sweep — artifact #5 and the completeness critic** (AI-355). Every run now answers with **two deliverables, never one**: the access-gate verdicts *and* a solution-space map of what already exists. New artifact `research-solution-space.json` (schema `tests/schema/research-solution-space.schema.json`), emitted on **every** run — including a `not-applicable` geometry, where it records the declaration and its reason instead of a sweep. New **Phase 1b** executes a closed six-category sweep (`platform-official-api`, `own-stack`, `open-source`, `mcp-registries`, `commercial-vendors`, `substitution-channels`) with the **own-stack grep ordered first, before any web call** (`scripts/stack_inventory.py`, stdlib + zero network; absent `~/.claude/deep-research/stack-paths.json` → `degraded`, never a silent `empty`). New **Phase 5b** runs a decorrelated completeness critic on a different Claude model whose sole mandate is to name uncovered categories, countersign every `waived` status and challenge a `not-applicable` declaration. New doctrine `references/solution-space.md`; new gate `verify_gates.py check-solution-space` + `tests/check-solution-space.sh` with 12 adversarial fixtures; new regression corpus `evals/fixtures/sota-recall/` (4 ground-truth items from two real July-2026 misses). Queries are written in **capability-class vendor vocabulary, never the problem's own words** (B14), and a category is `empty` only alongside a passing control query (B17).
- **Phase-6 Artifact render.** After the artifacts are written and both gate verdicts quoted, the run publishes ONE self-contained private Artifact page (report + solution-space benchmark table + obligations header + waived-category count + both verdicts). Skipped on `--confidential` (publishing is egress) and when the Artifact tool is absent (headless surface); either skip is recorded in the Methodology note, and a missing Artifact never fails the run. `Artifact` and `Skill` added to `allowed-tools`.
- **`references/provenance.md`, `references/edge-cases.md`, `references/flags.md`** — three new reference files created by the D3 remediation below (see *Changed*).

### Added — auto-comptabilité: a run hands over its own cost anatomy (AI-372 / PRD-refonte R6, ratified 2026-08-17)

- **`scripts/run_accounting.py` → `research-run-accounting.json`, emitted at Phase 6 step 4.** The 2026-08 adoption eval had to mine a session transcript to answer "how much of a run is the engine, how much is the contract?" — and paid to derive it twice. The classification rule is now **ported verbatim** from the pre-registered instrument (`instrument/decompose-moteur-contrat.py`): engine = a step emitting ≥1 retrieval call (`mcp__tavily__*`, `mcp__scrapling__*`, `WebFetch`, `WebSearch`), contract = every other step, a step mixing both counts as engine — the same convention, so the two accountings stay comparable. Run metadata, **not a sixth artifact**: no gate, no contract surface, and `SKILL.md`'s "emit only the five artifacts" now says so explicitly. Stdlib, zero network, zero LLM (I4a), asserted by the test rather than promised.
- **It reports no token and no dollar figure, and that is the design, not a gap.** The PRD asked for a cost vector; a run cannot compute one. Token totals live on the session `result` event, which the running agent never observes, and per-message `output_tokens` in a transcript are streaming snapshots that under-report by orders of magnitude (measured 2026-08: **283 cumulative against 155,052** at `result`). The dominant item — 76% context carry — is a property of the whole conversation, not of any step. So the artifact carries counts, plus a `not_measurable_in_run` block naming *why* each figure is out of reach and pointing at the offline instrument: declared, never silently absent. `shares.basis` refuses the cost reading in the file itself, because a call share is not a cost share — the engine emitted a large fraction of the calls while costing ~14% of the run, and conflating the two is the error the eval had to correct.
- **Guards:** `tests/check-run-accounting.sh` (5 cases — classification incl. the mixed-step convention, **a ban on any cost/token key anywhere in the output**, rule provenance travelling with the data, empty-run degradation to `null` shares rather than a fabricated 0%, loud failure on malformed input), red-ability proven by mutating the mixed-step convention. `e2e-16` carries the DoD, and its load-bearing half is the negative one. `SKILL.md` absorbed the new Phase-6 step at **net-zero lines**, so the 150-line budget gate still passes.
